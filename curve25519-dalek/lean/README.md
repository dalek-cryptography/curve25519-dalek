# Lean verification of curve25519-dalek

Theorems about curve25519-dalek's public API in Lean 4, proved against an
[Aeneas](https://github.com/AeneasVerif/aeneas) translation of the Rust code.

## What to read

Everything a reviewer needs is in `ForHumans/`, about 4,000 lines. Nothing else needs to be read.

1. **`ForHumans/Theorems/Basic.lean`** (60 lines): how to read a theorem, what to check about the
   invariants, and why the generated copies need not be read.
2. **`ForHumans/Specs/`**, the definitions the theorems use, with no proofs:
   - the mathematics (520 lines): `Constants`, `Bytes`, `Field`, `Curves` (edwards25519,
     curve25519), `Models`, `Edwards` (basepoint, RFC 8032 encoding), `Montgomery`, `X25519`
     (RFC 7748), `Ristretto` (RFC 9496), in import order;
   - `Representation/` (600 lines): the value of a Rust value, e.g. the point an `EdwardsPoint`
     represents, the number a `Scalar` represents, the bytes of a byte array; and the invariants
     the theorems assume and guarantee: the bounds on the limbs (`IsBounded`) and what the
     precomputed tables hold (`IsTable`, `IsValid`);
   - `External/` (640 lines): what is assumed about the crates dalek calls (`subtle`, `zeroize`,
     `alloc`): their signatures, a contract per function, restating its documentation, and one
     axiom per crate saying that the contracts hold.
3. **`ForHumans/Theorems/`** (2,200 lines): one file per Rust file, a theorem per public item:
   `Scalar`, `Edwards`, `Montgomery`, `Ristretto`, `Constants`, `Traits`. `Axioms.lean` checks that
   the theorems use no other axioms, `Definitions.lean` that they use no definition outside
   `ForHumans/Specs/` (and the translation and the libraries).
4. Optionally, **`ForHumans/TestVectors.lean`** (470 lines, mostly hexadecimal): the definitions
   of `ForHumans/Specs/` on the test vectors of RFC 8032, RFC 7748 and RFC 9496, written as the
   RFCs write them, to compare line by line with the RFCs.

The curve models (`TwistedEdwardsModel`, `MontgomeryModel`), their group laws, the extended
coordinates and the Montgomery ladder come from the
[`EllipticCurve`](https://github.com/Beneficial-AI-Foundation/elliptic-curve) library, whose
definitions are part of what is trusted.

Not to be read:

- the copies of each file for the three other configurations, in `ForHumans/Theorems/<File>/` and
  `ForHumans/Specs/Representation/<File>/`: `scripts/gen-config-specs.py` generates them from the
  `x86_64-tables` file by renaming, and CI checks that they are up to date;
- `Proofs/`: the proofs, the lemmas they use, the internal point types
  (`Proofs/Representation/`), and the kernel computations behind `ForHumans/TestVectors.lean`
  (`Proofs/Curve25519/TestVectors/`);
- `Curve25519Dalek/`: the translation, generated by Aeneas (CI checks that it is up to date).

## Layout

| Library | Content |
|---|---|
| `ForHumans` | `Specs/` (definitions), `Theorems/` (statements) and `TestVectors.lean`, as above. |
| `Curve25519Dalek` | The Aeneas translation (`Funs.lean`, `Types.lean`, generated). `FunsExternal.lean` and `TypesExternal.lean` are imported by name by the translation; `FunsExternal.lean` re-exports `ForHumans/Specs/External/`. |
| `Proofs` | Everything else: one proof file per Rust item, `Helpers/`, `Curve25519/` (the facts about the definitions, `Certificates/`, `TestVectors/`), `Representation/` (internal point types, unfolding lemmas), `External/` (the contracts as theorems). |

## Building

Build from this directory with `lake exe cache get && lake build`. Check the generated copies with
`scripts/gen-config-specs.py --check`, and regenerate them with `scripts/gen-config-specs.py`.

The Aeneas version is pinned in `AENEAS_VERSION.txt`. To regenerate the translation:
`scripts/aeneas-install.sh`, then `scripts/aeneas-translate.sh`.
